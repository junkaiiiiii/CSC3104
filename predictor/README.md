# predictor
Lead: Sook Yee.

Forecast future per-function bucket counts using only historical data. Moving average first; seasonal/ARIMA models later.

## Run
All commands run from repo root. Standard library only, Python 3.9+.
```bash
# Run on tuning dataset
python -m predictor.main --run-id tuning_seed101 --input telemetry/data/synthetic/tuning_seed101/demand_buckets.jsonl --window-size 3

# Run on heldout test dataset
python -m predictor.main --run-id heldout_seed202 --input telemetry/data/synthetic/heldout_seed202/demand_buckets.jsonl --window-size 3

# Window size sweep for evaluation
python -m predictor.main --run-id tuning_w5 --input telemetry/data/synthetic/tuning_seed101/demand_buckets.jsonl --window-size 5
python -m predictor.main --run-id tuning_w10 --input telemetry/data/synthetic/tuning_seed101/demand_buckets.jsonl --window-size 10

# Run unit tests
python -m unittest discover -s predictor/test -t .
```

## Input Contract (from Telemetry)

For a live run, use a **new run ID** and follow the collector's append-only file:

```bash
python3 -m predictor.main --run-id predictive-17 \
  --input telemetry/data/predictive-17/demand_buckets.jsonl --window-size 3 --follow
```

`--follow` waits if the input does not exist yet, waits for a newline before consuming
each record, and flushes every forecast immediately. Ctrl+C closes the output.
Output files must not already exist; use a new run ID rather than overwriting one.
`--output` can select an explicit new output file.

Incomplete, duplicate and out-of-order buckets do not emit forecasts. A gap or
interval change resets that function's SMA history rather than treating missing
data as zero demand. Malformed JSON is reported and skipped; invalid bucket fields
stop the process and need investigation.

Live output includes the existing audit fields plus the shared forecast contract:
actual UTC `generated_at`, `history_end`, `interval_seconds`, `model`, `predictions`
and `valid_until`. The SMA value is held constant for two intervals after history
ends. The first interval has already started by the time telemetry finalises it;
the second is a future horizon. Expired backlogs and future-ended history are not
published as live forecasts. This is a persistence baseline, not a model that can
anticipate the first burst after a long quiet period. Batch output remains in the
original compact format, whose availability time the scheduler estimates.

Reads `demand_buckets.jsonl` generated by Felix's telemetry collector. Each line is a finalised 30s demand bucket:
| Field | Type | Description |
|---|---|---|
| `function_id` | string | Unique ID of the serverless function |
| `bucket_start` | ISO8601 UTC | Start timestamp of the 30s bucket |
| `interval_seconds` | int | Bucket length (fixed at 30s) |
| `invocation_count` | int | Total valid user requests in this bucket |
| `complete` | bool | `false` if bucket overlaps a data gap (skipped by predictor) |

---
## Output Contract
Writes `forecasts.jsonl` to `predictor/data/<run_id>/`. Each line is a forecast for the next upcoming bucket:
| Field | Type | Description |
|---|---|---|
| `function_id` | string | Function the prediction applies to |
| `forecast_bucket_start` | ISO8601 UTC | Start timestamp of the predicted next bucket |
| `forecast_invocation_count` | float | Predicted average request count for the next bucket |
| `window_size` | int | SMA window size used for this prediction |
| `input_buckets_used` | list | Audit trail: historical buckets used to calculate the forecast (proves no future data is used) |

Example output line:
```json
{"function_id": "periodic", "forecast_bucket_start": "2026-10-01T00:01:30Z", "forecast_invocation_count": 0.67, "window_size": 3, "input_buckets_used": [{"bucket_start": "2026-10-01T00:00:00Z", "invocation_count": 1}, {"bucket_start": "2026-10-01T00:00:30Z", "invocation_count": 0}, {"bucket_start": "2026-10-01T00:01:00Z", "invocation_count": 1}]}
